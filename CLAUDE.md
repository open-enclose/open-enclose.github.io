# open-enclose.github.io

The public artifact for Baker & Conning, *A Model of Enclosures*. The `enclose` package, its
tests, the site narrative, and the mathematical appendix. Published at
<https://open-enclose.github.io/> — which is what the paper's own footnote cites, so this
repository **is** the online appendix.

Run tests with `mamba run -n ecopy python -m pytest tests/ -q`. **184 should pass.**

## Invariants — violating these has already happened once each

**The appendix exists here and nowhere else.** `content/04-derivations.md` is canonical.
A second editable copy lived in `enclosure_book/docs/online_appendix.md` until 2026-07-29;
the two silently diverged and had to be reconciled by hand. That path is now a pointer stub.
Do not recreate a second copy.

**The governance wedge $A_\mu = 1-\mu(1-\alpha)$ is not optional.** $\Lambda_\mu$ carries
$\mu$ into the *slope* of the agricultural labor allocation; $A_\mu$ carries it into the
*level* of what labor earns. The shorthand for the agricultural return that omits it is exact
only at $\mu=0$, where the prefactor happens to equal 1. Dropping it overstates the planner's
labor demand by $1/\alpha$ and inverts the welfare comparison. See
`enclose/manufacturing.py::commons_wedge`.

**Two thresholds, two different signs. Do not reconcile them.**

- Labor allocation: $\operatorname{sign}(\partial l_m/\partial t_e) = \operatorname{sign}(1-\Lambda_\mu)$, turning at $\theta_H^\mu$. Note the inversion — the equilibrium condition's left side rises in $l_m$, so $l_m$ rises when $C_a$ *falls*.
- Enclosure margin: $\operatorname{sign}(dY/dt_e) = \operatorname{sign}(\Lambda_o - 1)$, turning at $\theta = 1$.

These answer different questions — *which way does enclosure push labor* versus *is enclosure
worth doing*. The first was stated backwards across six files until 2026-07-29; the second is
correct as written and must not be "fixed" to match.

**Conditional on $t_e$ is load-bearing.** Full enclosure reproduces the planner's *labor*
allocation for any $\theta$ — but the planner encloses nothing at all when $\theta \le 1$ and
$c>0$. Do not let the first claim imply the second.

**The computation path must stay matplotlib-free.** `enclose.model`, `enclose.numerics` and
`enclose.loci` must not import matplotlib, directly or transitively. `safe_log_power` lived in
`enclose.style` (which imports `matplotlib.patches`) until 2026-07-29, so evaluating a single
locus dragged in the whole plotting stack — a large, pointless download under Pyodide.
`tests/test_imports.py` guards this **in a subprocess**; an in-process check would pass
vacuously, because every other test file imports matplotlib for its own reasons. Put pure-numpy
helpers in `enclose.numerics`, never in `enclose.style`.

**The site build needs mystmd ≥ 1.10, and the failure is silent.** `project.static_files` —
which copies `pyodide/enclose-0.1.0-py3-none-any.whl` to the site root for the explore page —
is ignored by 1.9.x with only a warning. The build succeeds and the page 404s at runtime. CI
pins `mystmd@^1.10`. Also note the wheel is a **committed binary that goes stale**: rebuild it
(`python -m build --wheel`) whenever `enclose/` changes, or move the build into `deploy.yml`.

## Figures: not settled

`Figures/` is generated by `enclose/figures.py` via `scripts/make_figures.py`. **Matthew
Baker maintains a parallel set** in the private `jhconning/enclosure_notebooks`, produced by
notebooks that do not import this package and carry their own copies of `safe_log_power`,
`style_axes`, `common_labels`, `fill_between_sorted`. All eight shared figures differ
byte-wise; one visual comparison found identical loci and only a changed axis label.

**Which set is canonical is unresolved and is Jonathan's conversation to have with Matt.** Do
not assume this package wins, and do not regenerate `Figures/` into the repo as if it does.

## Conventions

- Stage with targeted `git add`; never `git add -A`.
- The interpretation of the manufacturing results — regimes, historical readings, the
  dual-economy framing, the research agenda — lives in `enclosure_paper/notes/manuf_paper_ideas.md`,
  deliberately not in the appendix. A derivations appendix is the wrong home for it.
- These repositories sit on a Google-Drive-synced path, which has written `[Conflict]` files
  into `.git` before. If git reports bad refs, look for those first.
